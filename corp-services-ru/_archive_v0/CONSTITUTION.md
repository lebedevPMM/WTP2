## 1. Non-Negotiable DNA

### 1.1 Banking-First остаётся differentiator
- Любой generic перевод «делаем UAE-инфраструктуру» = слив в общий рынок (там 200+ агентств).
- Hero MUST содержать сигнал банковской компетенции в первых 10-15 словах.
- 5 buckets могут идти в порядке Сергея (компания → банкинг → резидентство → опс → частные), НО над ними должен стоять **meta-layer** «как мы делаем» — и там Banking-First Diligence как первый шаг до регистрации компании.
- **Test:** прочитай hero вслух → если можно вставить логотип любого другого UAE-сетап агентства без редактуры — провал.

### 1.2 Outcome language > technical language
Сергей прав: «bankable structure» — внутренний термин. Клиент думает:
- «чтобы банк не заблокировал»
- «чтобы счёт не закрыли через 3 месяца»
- «чтобы компания не развалилась»
- «чтобы налоговая не пришла»
- «чтобы не переделывать потом»

→ Headlines и subheads MUST вести outcome-словарём. Технический термин допустим только когда внутри объяснения метода («Pre-Screen / банковский маршрут / KYC-подготовка»), не в title.

### 1.3 Этот сайт — НЕ дубликат wtp.ae
- wtp.ae = англоязычный HNWI relocation (Wealth Transfer, banking-first для индивидуального HNWI).
- corp-services-ru = русскоязычный **корпоративные услуги для СНГ-бизнеса** (предприниматель/группа компаний переводит/строит инфраструктуру).
- Аудитория частично пересекается, но angle другой: тут **бизнес как клиент**, а не privately HNWI.
- → отдельный домен, отдельный voice, отдельная сетка продуктов (B2B-tone, не private-client-tone).

### 1.4 Платформа кейсов = первоклассный объект, не блог
Сергей: «сделаем как платформу для выгрузки кейсов по открытию компаний, лицензий и т.д.»
- Кейсы — это **proof-engine**, не контент-маркетинг.
- Каждый кейс = отдельная страница с фиксированным шаблоном (см. `CASE-TEMPLATE.md`).
- На главной — last 6 + filter by service.
- URL: `/cases/{slug}` (предсказуемо, sharable, SEO-friendly).

## 2. Voice & Tone

### MUST
- Russian, грамотный деловой, без англицизмов где есть нормальный RU-эквивалент (закон №52-ФЗ + Сергеев тон).
- Конкретные сроки, цифры, юрисдикции. «Открываем счёт за 4-8 недель» > «быстро открываем счёт».
- Именные эксперты (Burnside-паттерн): Иван / Оля / Олег / Илья / Костя — на каждом кейсе и в авторстве разделов.
- Деловой консультативный, не sales-pitch. Тон Burnside, не тон digital-агентства.

### NEVER
- ❌ «комплексное сопровождение», «премиальный сервис», «доверьте нам», «эксперты с многолетним опытом», «надёжный партнёр»
- ❌ восклицательные знаки
- ❌ эмодзи в основном контенте
- ❌ «bankable structure» как термин в client-facing копи (он остаётся для professional audience: партнёры/брокеры/юристы — там можно)
- ❌ generic UAE-setup словарь: «turnkey», «one-stop-shop», «full-service», «360°»

### Hero-headline anti-patterns (специально)
- ❌ «Создаём международную бизнес-инфраструктуру с центром в ОАЭ» — Сергеев черновик, generic, любая фирма скажет.
- ❌ «Откройте компанию в Дубае» — категория, не offer.
- ❌ «Полный цикл услуг для бизнеса в ОАЭ» — слив в шум.
- ✅ Hero должен **в первой строке** сигналить уникальный метод (Banking-First) **или** уникальный outcome («компания, которая не разваливается после регистрации»).

## 3. Audience Definition

**Primary:** Русскоязычный предприниматель / собственник бизнеса из СНГ, который:
- Уже думает о ОАЭ (не educate that ОАЭ exists)
- Боится конкретного: блокировки счёта, отказа в KYC, налоговых проблем, сломанной структуры
- Был обожжён или знает обожжённого (типичная история: «нам открыли компанию, а счёт не открыли» / «открыли, а через 3 месяца заморозили»)
- Готов платить за «правильно», но устал от «впаривания»

**Secondary:** Юрист / финансовый консультант / брокер в СНГ, который ищет надёжного UAE-партнёра для клиентов.

**NOT this page:** Solo HNWI индивидуально переезжающий с семьёй (это wtp.ae EN). Solo нерезидент без бизнеса (это TRC trc.wtp.ae).

## 4. Page Structure — Sergey's 5 Buckets, Confirmed

Порядок секций — Сергея, мы согласны:

1. **Регистрация компании** (mainland / freezone / лицензии / структура владения)
2. **Банковская инфраструктура** (счета / KYC / банковский маршрут / международные расчёты)
3. **Резидентство и документы** (визы / Emirates ID / Golden Visa / family residency)
4. **Операционное сопровождение** (продления / бухгалтерия / compliance / support)
5. **Частные вопросы клиентов** (недвижимость / доверенности / наследование / семейные структуры)

**НО:** над этими 5 buckets — meta-section «Как мы это делаем» с Banking-First Diligence как первым шагом ДО регистрации компании. Это сохраняет DNA без перестановки Сергеевой структуры.

## 5. Conversion Architecture

### Single primary CTA
**«Pre-Screen за 30 минут — бесплатно»** — quick qualifying call с Иваном или Олей.

Не «оставьте заявку», не «получите консультацию», не «свяжитесь с нами».
Pre-Screen — это уже **продукт** WTP, а не lead-magnet.

### Secondary CTAs
- На каждом кейсе: «обсудить аналогичную ситуацию» → Pre-Screen
- В футере: WhatsApp / Telegram прямые контакты (Сергей / Иван)
- В meta-секции «Как мы это делаем»: «скачать карту банковского маршрута» (PDF) — единственное место где допустим download

### Form-to-Bitrix
- Repeat trc.wtp.ae pattern: standalone HTML/JS + CF Function proxy → Bitrix24 webhook
- Webhook: `https://wtp.bitrix24.ru/rest/6729/zp94gye6ag0cxdr0/` (тот же что TRC использует)
- **Decision pending:** на кого падают лиды (не на Константина — см. предыдущая сессия 13.05 утром, было решено перенастроить).
- 3 поля: имя / контакт (WhatsApp/Telegram/email) / 1 строка «что нужно».
- UTM-теги обязательно (для каждого канала — телеграм, реклама, кейс-страница, главная).

## 6. Technical / Deploy Architecture — Decision Needed

### Recommendation (мой default — Сергей confirms)
- **Standalone repo:** `lebedevPMM/wtp-corp-ru` (повтор паттерна wtp-trc / wtp-ceo / wtp-local).
- **Domain:** `corp.wtp.ae` (ru content на `.ae` домене — нормально, RU = язык, не TLD). Альтернатива: subdomain на `wtpref.ru` если хотим RU-домен. Я бы взял `corp.wtp.ae` чтобы держать всё в одной CF Pages экосистеме (5 проектов уже там).
- **Stack:** static HTML/CSS + минимум JS + CF Function для лидов (не React/Vite — overhead не нужен, кейсы = markdown → HTML генерация).
- **Case rendering:** статическая генерация из MD-файлов в `/cases/*.md` через build script (Node), не CMS. Сергей пишет MD → коммит → деплой автоматом через CF Pages git integration.

### Open decision points (P0, нужно от Ивана/Сергея)
1. **Domain:** `corp.wtp.ae` ИЛИ `wtpref.ru/corp` ИЛИ свой `.ru` домен?
2. **Lead routing:** на кого в Bitrix падают заявки? (не на Константина — это уже договорились)
3. **Имена-авторы на кейсах:** разрешаем публиковать ФИО клиентов под кейсами или анонимизируем? (юристы обычно анонимизируют — «предприниматель из РФ, IT-сектор, $X в год оборот»)
4. **EN-версия:** когда-нибудь делаем дубль на английском или RU-only forever?

## 7. Quality Gates (audit-debate goals)

Финальный v1 проходит, когда:

### Gate 1 — Banking-First DNA сохранён
- В hero есть явный сигнал банковской компетенции (Pre-Screen / банковский маршрут / banking-first / 4-8 недель счёт)
- В meta-секции «Как мы это делаем» Banking-First Diligence — первый шаг
- Минимум 1 банковский кейс в featured 6 на главной

### Gate 2 — Outcome language passed
- Все 5 заголовков bucket-секций — outcome-driven, не describe-the-service
- Hero не содержит generic фразу «создаём международную бизнес-инфраструктуру»
- Нет ни одной фразы из NEVER-листа (§2)

### Gate 3 — Sergey's structure honoured
- 5 buckets в его порядке, его именами секций
- Платформа кейсов = first-class, не «блог»
- Voice читается как Сергея бы прочёл: деловой, конкретный, без впаривания

### Gate 4 — Conversion mechanic clean
- Primary CTA = Pre-Screen (не «оставьте заявку»)
- На кейсах — CTA «обсудить аналогичную ситуацию»
- Форма 3-полевая, UTM-параметризованная

### Gate 5 — Differentiation от wtp.ae
- Не дублирует англоязычные блоки wtp.ae дословно
- Воспринимается как **B2B сервис для бизнеса**, не «индивидуальный HNWI relocation»

После двух параллельных v1 копи (V1A pain-led / V1B proof-led), синтез запускается через 4 голоса критики:
